# Помощник для Claude и Codex в Plasma

Локальный помощник для работы с Claude Desktop и Codex в KDE Plasma. Записывает микрофон и звук компьютера, расшифровывает речь на ноутбуке и добавляет текст в текущий черновик. Другие горячие клавиши прикрепляют снимок экрана, отправляют сообщение и управляют окном. Оба клиента открываются в своих штатных интерфейсах.

## Режимы

| Режим | Что открывается |
| --- | --- |
| **Обычный** | Окно Claude Desktop или Codex на текущем рабочем столе. В Plasma помощник закрепляет его поверх остальных окон, задаёт непрозрачность 90% и активирует окно при вставке. |
| **TigerVNC** | Тот же клиент на отдельном виртуальном X11-экране. На основном рабочем столе открывается локальный просмотрщик, который подстраивает разрешение виртуального экрана под свой размер. |

Горячие клавиши действуют в Plasma. В GNOME обычный ярлык Codex только открывает нужный чат. В каждый момент работает один режим с горячими клавишами. Чтобы переключить режим во время записи, сначала завершите её, затем откройте нужный ярлык.

## Установка

Этот репозиторий содержит скрипты интеграции для Ubuntu/Linux x86-64. Графические клиенты и движок распознавания устанавливаются отдельно.

### 1. Подготовить рабочий стол и клиент

Для полного режима нужна сессия **KDE Plasma 6.6+ на Wayland** с пользовательской службой `systemd`, PipeWire и порталом KDE. В Ubuntu необходимые пакеты можно установить так:

```bash
sudo apt install python3-dbus python3-gi gir1.2-atspi-2.0 pipewire-bin wireplumber kde-spectacle xdg-desktop-portal-kde xwayland libnotify-bin
```

Для виртуального экрана добавьте:

```bash
sudo apt install tigervnc-standalone-server tigervnc-viewer twm xauth x11-utils x11-xserver-utils libxtst6 ffmpeg
```

Установите нужный клиент и войдите в свой аккаунт. Скрипты ожидают следующие пути:

| Клиент | Команда запуска | Исполняемый файл |
| --- | --- | --- |
| Claude Desktop | `/usr/bin/claude-desktop` | `/usr/lib/claude-desktop/claude-desktop` |
| Codex | `/usr/bin/chatgpt` | `/usr/lib/chatgpt/ChatGPT` |

### 2. Разместить движок и модель

Клонируйте репозиторий в каталог, рядом с которым будут вспомогательные файлы Meetingly и модель:

```bash
gh repo clone shndo1337/claude-interview-helper
```

```text
parent/
├── claude-interview-helper/
├── meetingly-review/app/
│   ├── node_modules/electron/dist/electron
│   ├── node_modules/koffi/
│   └── vendor/transcribe/linux-x64/
│       └── libtranscribe.so
└── meetingly-local/models/
    └── nemotron-3.5-asr-streaming-0.6b-Q5_K_M.gguf
```

Для звукового моста использовались Electron 44.10.0, koffi 2.16.3 и нативная сборка transcribe.cpp 0.2.4 с её библиотеками бэкендов. Распознавание настроено на русский язык и четыре потока CPU. Исходники и инструкции по подготовке зависимостей есть в проектах [Meetingly](https://github.com/iskandaryv/meetingly-ai) и [transcribe.cpp](https://github.com/handy-computer/transcribe.cpp).

### 3. Выбрать чат для Codex

Если используете Codex, создайте в корне репозитория файл `runtime/codex-interview/thread.json` и подставьте UUID существующего чата. Это последний сегмент ссылки вида `codex://threads/<UUID>`.

```json
{
  "threadId": "00000000-0000-0000-0000-000000000000"
}
```

Оба ярлыка Codex открывают этот чат. В TigerVNC клиент использует собственный графический профиль в `runtime/workspace/codex-profile/`. При первом запуске может потребоваться вход. Для Claude выберите чат вручную.

### 4. Создать ярлыки и запустить

Из корня репозитория выполните:

```bash
/usr/bin/python3 install-launcher.py
```

Скрипт создаёт четыре пользовательских ярлыка в `~/.local/share/applications/`. Флаг `--codex-only` создаёт только ярлыки Codex. Чтобы собрать ярлыки и служебные приложения KDE в папку **«Plasma и инструменты»**, используйте:

```bash
/usr/bin/python3 organize-apps.py
```

Этот скрипт также создаёт ярлыки и сохраняет резервные копии изменённых настроек меню в `runtime/menu-layout-backups/`.

Выберите нужный ярлык в меню или используйте соответствующую команду из корня репозитория:

| Клиент | Обычный | TigerVNC |
| --- | --- | --- |
| Claude | `/usr/bin/python3 controller.py launch` | `/usr/bin/python3 workspace.py launch` |
| Codex | `/usr/bin/python3 controller.py launch --codex` | `/usr/bin/python3 workspace.py launch --codex` |

Откройте чат с доступным полем ввода. Если Plasma запросит доступ к клавиатуре в обычном режиме, подтвердите его в системном диалоге. Помощник использует это разрешение для локальной вставки через буфер обмена.

## Горячие клавиши

| Сочетание | Действие |
| --- | --- |
| **Ctrl+Alt+V** | Начать запись. Повторное нажатие завершает распознавание и вставляет текст в черновик. |
| **Ctrl+Shift+S** | Прикрепить снимок основного экрана к черновику. |
| **Ctrl+Alt+Enter** | Отправить текущий черновик. |
| **Ctrl+Alt+H** | Скрыть или показать окно. В TigerVNC также открывает закрытый просмотрщик. |
| **Ctrl+Alt+W** / **Ctrl+Alt+S** | Прокрутить чат на один шаг вверх или вниз в TigerVNC. |

Запись длится до 90 секунд. Микрофон и системный звук распознаются отдельно по мере поступления. Когда речь есть в обоих каналах, текст содержит подписи «Микрофон» и «Звук компьютера». Закрытие просмотрщика TigerVNC оставляет клиент и помощник запущенными. Для полного завершения выберите **«Выключить этот режим»** в контекстном меню ярлыка или замените `launch` на `stop` в команде запуска.

## Данные и диагностика

- TigerVNC использует Unix-сокет текущего пользователя. Сетевые порты VNC и X11 и обмен буфером между просмотрщиком и основным экраном отключены.
- Распознавание выполняется локально. Черновики попадают в выбранный клиент. Прикрепление изображения может начать его загрузку до отправки сообщения.
- Профили, журналы, записи, снимки, модели и локальная конфигурация исключены из Git. Временные аудиофайлы и снимки удаляются при штатной обработке.
- Если голос не распознаётся, проверьте стандартные устройства ввода и вывода, громкость и пути к модели и нативным библиотекам. При ошибке запуска смотрите `runtime/controller.log` или `runtime/workspace/session.log` и `runtime/workspace/controller.log` для TigerVNC.
- Если Codex открывает другой чат, проверьте `threadId` и доступность этого чата в используемом профиле. Если обычный Claude не принимает вставку, полностью выйдите из клиента и запустите его ярлыком помощника для включения доступности редактора.

## Проверка и исходники

```bash
/usr/bin/python3 -m unittest -v test_launch_modes test_live_audio
```

Тесты покрывают выбор режима, запрет переключения во время записи и потоковую передачу аудиоданных. Скрипты `verify-workspace.py` и `verify-viewer.py` проверяют виртуальный экран на локальном тестовом окне. Порядок запусков, результаты прежних проверок и заметки о переносе локальной истории Claude Code собраны в [CHANGELOG.md](CHANGELOG.md).

- [controller.py](controller.py) управляет захватом, черновиком и пользовательской службой.
- [workspace.py](workspace.py) запускает отдельный экран и просмотрщик.
- [kwin.js](kwin.js) настраивает горячие клавиши и поведение окон в Plasma.
- [live_audio.py](live_audio.py), [bridge.cjs](bridge.cjs) и [speech-worker.cjs](speech-worker.cjs) передают звук и распознают речь.

Речевой модуль использует подход и интерфейсы из Meetingly. Текст соответствующей лицензии сохранён в [LICENSES/Meetingly-Apache-2.0.txt](LICENSES/Meetingly-Apache-2.0.txt).
